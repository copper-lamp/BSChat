# 说话活动日志设计

## 目标

为服务端提供可用于后续优化的说话活动统计，同时移除会把普通丢帧误称为限流的日志。日志不包含语音内容，不逐帧输出常规日志；真实异常原因必须可区分、可计数。

## 推荐方案

按每段 PTT 说话活动维护统计，在活动结束时输出一条汇总日志。使用现有客户端 PTT 按下/松开控制消息作为活动边界，并由服务端处理这两类消息。若活动仍未结束时玩家断线、会话重置或被新活动替代，则以明确的结束原因收尾，避免遗失累计统计。重复按下、无对应按下的松开等控制消息不应产生负时长或伪造活动。

说话活动只跟踪音频传输统计，不推断语义上的字数或实际发声内容。当前客户端持续发送 Opus 帧期间不会附带 `AudioFlagStart` / `AudioFlagEnd`；本方案不要求修改音频帧协议标志，也不将其作为活动边界来源。

## 汇总日志字段

每段活动结束时输出单条结构稳定、便于检索的日志，至少包括：

- `speaker`：说话者 PlayerId/UUID；不要求玩家名称，也不记录音频内容。
- `reason`：正常 PTT 松开、断线、会话重置或其他明确收尾原因。
- `duration_ms`：活动开始到结束的时长。
- `received_frames`、`accepted_frames`：收到的音频帧数及进入抖动缓冲的帧数。
- `dropped_frames`：未接受帧总数，并按明确原因拆分，例如 `rate_limited`、`late_or_duplicate`、`buffer_overflow`、`invalid`。
- `opus_bytes`：本段收到的 Opus 载荷字节总数；统计边界在服务端收到消息时，避免误称为有效语音数据字节。
- `avg_fps`：`received_frames / duration_seconds`；时长为零时定义为 0，避免除零。
- `max_fps`、`frame_size_ms`、`jitter_depth_frames`：关联配置/运行状态，用于判读帧率和缓冲行为。

## 明确丢帧原因与日志降噪

移除 `pendingFrames()` 前后数量比较作为接收成功/失败依据。`PlayerSession`/抖动缓冲的接收接口应返回明确处理结果，使运行时可准确更新统计：帧率超限、序号迟到或重复、缓冲溢出/替换、成功入队等。日志不得将这些结果合并称为“rate limit”。

逐帧丢弃原因计入当前说话活动统计，不为每个帧打印警告。没有关联活动的音频消息仍应被计入明确的无活动/无会话诊断路径，但日志需避免形成逐包刷屏；服务端语音关闭或会话缺失属于会话级异常，使用聚合或限频日志，不冒充帧率限流。

实现时需明确区分“队列满导致驱逐旧帧”和“新帧被拒绝”：前者的新帧可能成功入队但造成一次旧帧丢弃，不能仅根据队列长度变化判断。

## 组件与数据流

1. 客户端继续用现有 PTT pressed/released 控制消息表达按住说话边界，无需变更网络协议。
2. `ServerRuntime::handleControl` 将控制消息交给对应玩家会话的活动统计生命周期。
3. `ServerRuntime::handleAudio` 根据 `peerId`、序号、flags、Opus 字节数和 `PlayerSession` 明确返回的结果，更新该说话者当前活动统计。
4. `PlayerSession`/`JitterBuffer` 提供足够明确的入队结果和丢弃/驱逐原因；其职责仍是帧率保护和抖动缓冲，不直接格式化日志。
5. 说话活动统计组件在边界处生成汇总日志，通过现有 `LogSink` 输出；服务端适配层现有 logger 与文件日志继续负责落地。
6. 会话销毁或重置时结束尚未收尾的活动并清理状态，防止玩家统计泄漏到后续会话。

所有按玩家维护的活动与累计字段应在并发网络/游戏线程间安全访问，并遵循现有 `PlayerSession` 的锁保护约定，避免在持锁期间调用外部日志 sink。

## 测试与验收

- PTT 按下、若干音频帧、PTT 松开后，恰好生成一条汇总，玩家 ID、时长、帧数、字节数、平均帧率和运行参数正确。
- 各类帧处理结果分别计入对应丢弃原因；队列满驱逐与限速拒绝不能混淆。
- 正常说话期间不出现逐帧的模糊“rate limit or invalid frame”警告；结束时仍能看到汇总。
- 重复 pressed、孤立 released、无效帧、活动中断线/重置、零时长活动均不会导致重复汇总、负时长或除零。
- 并发音频到达与说话边界处理保持统计一致；结束后的新活动不继承上一段统计。
- 在现有 host 测试 target 中补充运行时和会话测试；运行相关测试，并执行项目已提供的构建、lint/typecheck 检查（如有）。

## 范围与非目标

本设计只增加服务端说话活动与传输质量统计，不保存、记录或转写音频内容，不修改协议格式，不新增玩家名称查找，也不实现逐帧日志或新的管理界面。
